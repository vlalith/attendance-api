# REVIEW.md

Defects found in the starter `app/main.py`:

| # | Where (function / line) | What is wrong | How you would notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` (lines 73-74) | Mongo is never actually pinged. The handler always returns 200 OK even if the database is unreachable or down. | Shut down the local MongoDB daemon; `GET /health` still returns `{"status": "ok"}`. | Wrapped `client.admin.command("ping")` in a try/except block, returning HTTP 503 on connection failure. |
| 2 | `create_employee()` (lines 79-85) | Check-then-insert race condition between `find_one` and `insert_one`. Two concurrent requests for the same `emp_code` can both pass validation. | Fired concurrent POST requests with the same `emp_code`; both succeeded with 201 and created duplicate records. | Removed the manual `find_one` check entirely; relied on the unique index on `emp_code` and caught `DuplicateKeyError` to return 409. |
| 3 | `create_employee()` (line 82) | Using `datetime.now()` produces a naive local timestamp. On a non-UTC system, PyMongo stores the local time offset as if it were UTC. | Checked the stored document when running in IST (+05:30); the saved `created_at` was off by 5.5 hours. | Switched to `datetime.now(timezone.utc)` for consistent UTC timestamps. |
| 4 | `create_employee()` (lines 84-85) | `created_at` is returned as a Python datetime object rather than epoch milliseconds (integer). | Calling `POST /employees` returns an ISO string like `"2026-07-06T09:40:00"` instead of an integer. | Converted `created_at` using `dt_to_ms()` before returning the response. |
| 5 | `list_employees()` (line 93) | Off-by-one error in pagination: `skip = page * page_size`. Page 1 skips `page_size` items instead of 0. | Calling `GET /employees?page=1` skips the first batch and returns page 2 results. | Changed calculation to `skip = (page - 1) * page_size`. |
| 6 | `list_employees()` (line 94) | `count_documents({})` counts the entire collection instead of the filtered query. | Filtered by department (e.g. Engineering); `total` reflected all employees in the DB, not the department subset. | Passed the active filter query `q` into `count_documents(q)`. |
| 7 | `list_employees()` (line 97) | `created_at` is returned as a raw datetime in list responses. | Inspected `GET /employees` response items; `created_at` fields were ISO strings rather than epoch ms integers. | Ran each returned document through `serialize_employee()` before sending. |
| 8 | `punch_in()` (line 102) | `datetime.fromtimestamp()` defaults to local system timezone instead of UTC. | Sent an epoch ms timestamp from an IST machine; the stored BSON date was skewed by 5.5 hours. | Used `datetime.fromtimestamp(ms / 1000, tz=timezone.utc)` via the `ms_to_dt` helper. |
| 9 | `punch_in()` (line 103) | Attendance date calculation uses UTC date directly and fails for overnight shifts. | For EMP0005 (night shift 22:00-06:00), punching in at 05:30 IST got assigned to today rather than yesterday's shift. | Implemented `attendance_date()` helper to convert to IST and apply shift boundary rule R1. |
| 10 | `punch_in()` (line 119) | Returns stringified MongoDB ObjectId (`doc["id"] = ...`) which violates the response schema. | Calling `POST /attendance/punch-in` produced an unexpected `"id"` field in the JSON response. | Dropped the id assignment and sanitized through `serialize_record()`. |
| 11 | `punch_in()` (line 100) | Missing check for non-existent employee. If `emp` is `None`, `emp["shift_start"]` crashes with TypeError. | Punched in with an unregistered `emp_code`; server threw an unhandled 500 error instead of 404. | Added an explicit check: `if not emp: raise HTTPException(404, "Employee not found")`. |
| 12 | `compute_late_minutes()` (line 35) | Naive datetime `replace()` mixes timezone-aware and naive objects, raising a TypeError. | Tested late calculation with an aware datetime object; the subtraction crashed with a TypeError. | Ensured arithmetic happens consistently with IST-aware datetime objects. |
| 13 | `compute_late_minutes()` (line 37) | Grace period check used float division and `int()` truncation instead of floor division. | Punches right around the 10-minute boundary (e.g. 10.5 min) behaved inconsistently. | Used integer floor division `int(diff_seconds // 60)` and checked strictly `> 10` (R2). |
| 14 | `compute_overtime()` (line 46) | `shift_end` was placed on the punch-in calendar date without checking for overnight shifts. | For EMP0005 (22:00-06:00), punching out at 06:40 next morning calculated over 24 hours of overtime. | Detected overnight shifts (`shift_end < shift_start`) and added 1 calendar day to the end date. |
| 15 | `list_attendance()` (lines 144-146) | Fetches the entire collection into Python memory before sorting and slicing. | On large datasets this would exhaust server RAM and introduce heavy latency. | Replaced in-memory slicing with cursor-level `.sort().skip().limit()`. |
| 16 | `department_trend()` | Mongo `$densify` range bounds were passed `$dateFromString` expression objects. | Running `GET /analytics/departments/{dept}/trend` crashed MongoDB with OperationFailure (code 5733402). | Built BSON UTC datetime objects in Python and passed them directly into the bounds array. |
| 17 | `explain_endpoint()` | PyMongo 4 removed `explain=True` on `aggregate()`, and raw BSON UUIDs cause UnicodeDecodeError. | Calling `GET /admin/explain/employee_monthly` threw ConfigurationError or UnicodeDecodeError. | Used `db.command("aggregate", ..., explain=True)` and sanitized the output using `bson.json_util`. |

### Items reviewed and decided NOT a defect

- **`compute_work_hours` using `round()`**: Python uses banker's rounding (round half to even). While not yet called from a complete flow in the starter skeleton, I replaced it with `half_up_round()` to ensure correct payroll calculations (R4).
- **`IST = timezone(timedelta(hours=5, minutes=30))`**: Offset is correctly defined (+05:30); kept as-is.
